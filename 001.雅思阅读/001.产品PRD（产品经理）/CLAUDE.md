# CLAUDE.md · 产品 PRD

This file provides guidance when Claude Code works inside this folder and its subfolders.

## 范围

本目录收录**产品类项目**的 PRD 文档与对应实现。每个产品一个子文件夹，PRD 与实现一一对应。

## 目录约定

```
00X.产品PRD/
├── CLAUDE.md                          ← 本文件（产品总览）
├── <产品名>-PRD.md                    ← 该产品的源 PRD（v1.0 起与产品同目录）
└── <产品名>/                          ← 该产品的实现
    ├── CLAUDE.md                      ← 产品级局部指引
    ├── index.html / 源码 / 数据
    └── ...
```

新加产品时，按以下顺序：

1. 在本目录放 `<产品名>-PRD.md`（用现有 PRD 做模板；可向用户索取 `1.产品概述 / 2.目标用户 / 4.功能需求 / 9.版本规划` 等章节）
2. 再建 `<产品名>/` 子文件夹放实现
3. 不要把多个产品混在同一个子文件夹里

## 跨产品规则

- **不做营销/SEO/付费墙**：所有产品均为个人学习工具，无商业化
- **内容来源谨慎**：PRD 涉及版权内容（真题、教材节选）时，默认采用「**自撰 / 用户导入**」路径，不直接分发原文
- **技术栈**：与仓库根 `CLAUDE.md` 一致——单文件 HTML 优先、零依赖、零构建、内嵌 CSS/JS
- **响应式**：移动端优先，与 `001/` 文件夹下的游戏布局风格保持一致（`fitBoard` 类自适应思路不适用非游戏产品，但「顶部栏 + 主区 + 底部控制条 + 抽屉/侧栏」的整体节奏可借鉴）
- **数据持久化**：所有用户级数据（进度、收藏、偏好）放 `localStorage`，命名 `<产品>-<字段>`（如 `ielts-reader-progress`）
- **PRD ↔ 实现同步**：PRD §9 版本规划若变更，应回写实现；不要静默偏离 PRD

## 与根 CLAUDE.md 的关系

- 根 [`CLAUDE.md`](../CLAUDE.md) 给出整个仓库的通用约定（架构、运行、风格）
- 本文件只规定**产品类项目**的组织方式
- 各产品子文件夹里的 `CLAUDE.md` 只规定**该产品**的实现细节
- 加载优先级：根 → 本文件 → 产品子文件夹 CLAUDE.md（Claude Code 自动就近合并）
