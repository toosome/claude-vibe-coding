## 1. 产品概述

### 1.1 背景

备考雅思的考生普遍在阅读环节遇到两个痛点：

1. **读得懂单词、读不懂句子**：长难句成分复杂，从句嵌套多，考生无法快速判断「谁修饰谁、谁做谁的成分」，导致理解偏差。
2. **被动读、无反馈**：传统精读靠老师逐句讲解，自学时缺乏「拆句」的工具，无法主动确认自己是否理解了句子结构。

市面上现有的语法高亮工具多为「整段一次性标注」，信息过载；本产品把拆句过程**节奏化**——一次只读一句，点读一句、拆解一句，降低认知负担，形成「主动理解 → 即时验证」的学习闭环。

### 1.2 产品定位

一款**面向雅思备考人群的「句子成分可视化精读」工具**：以剑桥雅思真题文章为载体，逐句点读，用颜色高亮 + 标签实时标注每个句子的语法成分，帮助用户拆解长难句、建立句子结构意识。

**一句话描述**：点读一句话，看清它的骨架（主干成分）和血肉（修饰成分）。

### 1.3 核心价值

- **结构可视化**：把抽象的语法成分变成一眼可见的颜色区块。
- **节奏化学习**：一次一句，主动点读，避免信息过载。
- **即时反馈**：点读即看到成分划分，随时验证自己的理解。
- **个人身份（v1.0.1 新增）**：注册登录后留下账号痕迹，让「学习积累」可被指认。

## 1.4 竞品分析

> 目的：理解同类产品的形态与定位，明确本产品「点读拆句」这一交互形态在赛道中的差异化价值，并为标注体系与交互设计提供参照。

### 1.4.1 竞品 1：English Sentence Analyser（英文句子成分分析器）

| 维度 | 内容 |
| --- | --- |
| 产品形态 | Web 工具（在线版 / 桌面应用） |
| 核心功能 | 输入英文句子 → 自动按短语结构（NP/VP/PP 等）拆解 → 渲染语法层级树 |
| 目标用户 | 语法学习者、语言学学生、ESL 教师 |
| 优势 | 拆分粒度细（短语结构层级）、可视化清晰、学术性强 |
| 不足 | 一次性铺开整句拆解结果，**信息密度高、视觉过载**；非雅思语料；缺节奏化学习设计；无进度/收藏等学习闭环；偏 PC 端，移动端体验弱；**无账号体系，所有数据丢失即清零** |

**与本产品的对比**：

| 维度 | English Sentence Analyser | 本产品 |
| --- | --- | --- |
| 学习节奏 | 一次性铺开所有成分 | **一次一句，节奏化推进** |
| 内容来源 | 用户输入任意英文 | 预置 / 自撰雅思风格文章 |
| 视觉表现 | 语法树 / 层级缩进 | 浅色底色 + 标签，颜色↔成分对照 |
| 学习闭环 | 无（纯工具型） | 进度 + 收藏 + 复习 + 断点续读 |
| 账号体系 | 无 | **v1.0.1 起邮箱 + 密码注册登录（本地 mock）** |
| 移动端 | 弱 | **移动端优先** |
| 适配人群 | 语法学者 / 语言学生 | **雅思考生 / 英语备考者** |

**对本产品的启示**：

- 借鉴其「成分系统化分类」思路（短语结构层级），作为本产品标注体系的参考输入。
- **避免一次性铺开所有成分**：坚持「一次一句」的节奏设计，是核心差异化壁垒。
- 强化雅思语境下的语料适配与备考场景结合，凸显「考点相关」价值。
- 视觉上避免复杂的语法树，采用更易读的「浅色底色 + 标签」方案，降低认知负担。
- 补齐学习闭环（进度 / 收藏 / 复习 / 断点续读），这是该竞品缺失但用户长期留存所需的关键能力。
- **v1.0.1 起的账号体系**是该竞品完全没有的「身份归属」维度，可作为后续差异化持续放大。

## 2. 目标用户与使用场景

### 2.1 目标用户画像

| 画像 | 描述 | 诉求 |
| --- | --- | --- |
| **核心用户**：雅思备考考生（目标 6.5–8.0 分） | 词汇量尚可，但长难句理解吃力，阅读速度慢 | 快速看懂句子结构，提升精读效率 |
| **次要用户**：英语学习者 / 四六级、考研英语备考者 | 有语法基础，需要巩固句子成分分析能力 | 用真实文章练成分划分 |
| **延伸用户**：英语教师 / 助教 | 需要备课、演示句子拆解 | 作为教学演示工具 |
| **v1.0.1 新增**：关注身份积累的备考者 | 长期备考、需要把学习记录留在账号下 | 注册登录后获得专属空间，未来可云同步 |

### 2.2 使用场景

1. **碎片化精读**：地铁/排队时，打开一篇雅思文章，逐句点读 10 分钟。
2. **长难句攻坚**：遇到看不懂的句子，点开它反复看成分划分，配合翻译和讲解理解。
3. **睡前复习**：回看今天收藏的难句，检验能否独立说出成分。
4. **v1.0.1 新增**：跨次会话保留身份——注册一次，下次打开自动登录，继续上次阅读进度。
5. **v1.0.1 新增**：个人学习痕迹沉淀——账号下挂着"我读过的句数 / 收藏的难句"，未来云同步后可在多设备查看。

### 2.3 用户故事

- 作为考生，我想**点读一个句子**，就能看到它的成分高亮，从而理解句子结构。
- 作为考生，我想**逐句推进**，读到哪儿划到哪儿，直到读完一篇完整文章。
- 作为考生，我想**查看每个成分的中文说明和例句提示**，从而学会这个语法点。
- 作为考生，我想**收藏难句**，之后集中复习。
- 作为教师，我想**隐藏/显示标注**，先让学生自己划分，再揭示答案。
- **v1.0.1 新增**：作为考生，我想**注册一个账号**，把"我正在备考"这个身份固定下来。
- **v1.0.1 新增**：作为考生，我想**下次打开自动登录**，不用每次都重新选文章、找进度。
- **v1.0.1 新增**：作为考生，我想**一键退出登录**，在共用设备上保护自己的账号痕迹。

## 3. 产品目标与成功指标

### 3.1 目标（v1.0.1 上线后 3 个月）

- 单篇文章的**完整读完率**（读完最后一句）≥ 40%。
- 用户单句平均**停留/思考时间** ≥ 5 秒（说明在主动阅读而非刷屏）。
- 难句**收藏/回看**行为占比 ≥ 20% 的会话。
- **v1.0.1 新增**：注册转化率（注册用户 / 访问用户）≥ 5%。
- **v1.0.1 新增**：注册用户的 7 日回访率 ≥ 30%。

### 3.2 北极星指标

**每日完成精读的句子数**（Sentences Read per Day）。

### 3.3 v1.0.1 子指标

- **账号创建数**：周维度新增注册账号数
- **登录成功率**：登录提交中成功进入学习页的比例（基线 ≥ 98%）
- **登录回访占比**：当日回访用户中已登录账号的比例

### 4.2 核心功能详述

#### 4.2.1 逐句点读（P0，核心）

（同 v1.0，未变）

- 一篇文章被划分为若干段落、若干句子。**初始状态**：仅第一句为「当前句」，处于高亮可读状态；其余句子以低对比度显示（可见但未标注）。
- 用户点击「下一句」按钮（或按 `空格键` / `→` 键，或直接点击目标句子）进入下一句。
- 进入新句子时，自动完成成分划分并渲染高亮；上一个句子变为「已读」状态（**仅保留句子原文，移除成分标注**；点击该句可回看并临时显示该句的标注）。
- **v1.0.1 hotfix**：默认进入「单句模式」，只有当前句显示成分标注；非当前句只显示原文。可通过「标注范围切换」按钮切到「全文模式」，全部句子显示标注。
- 支持**上一句 / 下一句 / 回到开头**；点击句子列表可**跳转**到任意一句。
- 读完最后一句时，出现「完成」提示与小结（本篇共 N 句、已读 N 句、收藏 M 句）。

> **设计原则**：每次只让一个句子处于「当前聚焦」状态，避免整屏花花绿绿。

#### 4.2.2 句子成分高亮系统（P0，核心）

（同 v1.0，未变）

对当前句的每个语法成分，用**浅色背景高亮 + 底部色条 + 悬浮标签**三层方式标记（详见第 5 章标注体系）：

- **高亮底色**：区分不同成分类型（配色见 5.3）。
- **成分标签**：每个高亮区块上方/下方可显示小字标签（如「主语」「定语从句」）。
- **嵌套展示**：当从句内还有更细成分时，外层用边框/下划线表示从句整体，内层用底色表示细分成分（MVP 可先做「扁平标注」，嵌套作为进阶）。
- **悬浮/点按 Tooltip**：查看该成分的名称、功能说明、中文含义示例。

#### 4.2.3 成分图例（P0）

（同 v1.0，未变）

- 页面提供可折叠的**图例面板**，列出所有成分类型及其对应颜色。
- 图例项可**点击开关**：点击某类成分（如「状语」）可单独高亮/隐藏该类成分，帮助用户聚焦特定语法结构。

#### 4.2.4 句子翻译与讲解（P1）

（同 v1.0，未变）

- 每句提供**中文翻译**，默认折叠，点击「译」按钮展开。
- 每句提供**语法点提示**（如「此处为 that 引导的宾语从句，作谓语 think 的宾语」），由标注数据附带。

#### 4.2.5 收藏与复习（P1）

（同 v1.0，未变）

- 点击句子旁的「☆」收藏难句；收藏的句子进入「我的难句」列表，可集中回看，回看时同样展示成分高亮。

#### 4.2.6 自主导入文章（P2，规划）

（同 v1.0，未变）

- 用户粘贴英文文本 → 前端自动分句 → 调用标注服务（AI/LLM）生成成分标注 → 进入同样的点读界面。
- **价值**：不受限于预置文章，也规避部分版权问题。

#### 4.2.7 用户系统（账号体系）— **v1.0.1 新增**

##### 4.2.7.1 账号数据模型

存储位置：`localStorage`，key 前缀 `ielts-reader-account-`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `email` | string | 用户邮箱，作为账号唯一标识 |
| `password` | string | **明文存储**（仅本机演示用，见 §8） |
| `nickname` | string | 昵称，默认取邮箱 @ 前部分，可后续修改 |
| `createdAt` | ISO string | 账号创建时间 |
| `lastLoginAt` | ISO string | 上次登录时间 |
| `currentArticleId` | string | 当前正在读的 article.id（用于登录后恢复进度） |
| `currentSentenceIdx` | number | 当前读到第几句（与现有 `ielts-reader-progress` 共存；登录态下优先读这一份） |

存储约束：

- 同一邮箱只能注册一次；注册时检测重复，重复则提示「该邮箱已注册，请直接登录」
- 全部账号以数组形式存在 `localStorage['ielts-reader-accounts']`（v1.0.1 演示场景下账号数极小，单 key 数组足够）
- 当前登录态：`localStorage['ielts-reader-current-account']` 存当前登录账号的 email

##### 4.2.7.2 注册流程（P0）

```
打开页面（未登录态）
   ↓ 看到顶栏右上角「登录」按钮
   ↓ 点击「登录」→ 弹出登录模态框
   ↓ 模态框底部有「还没有账号？立即注册」链接
   ↓ 点击「立即注册」→ 切换到注册表单
   ↓
注册表单：
   ┌─────────────────────────────┐
   │  邮箱 [___________________] │
   │  昵称（可选）[_____________] │
   │  密码 [___________________] │
   │  确认密码 [_______________] │
   │                             │
   │  [注册]   [返回登录]         │
   │                             │
   │  ⚠️ 提示：本工具为本地演示，  │
   │  账号仅保存在本机浏览器中     │
   └─────────────────────────────┘
   ↓ 校验通过 → 写入 localStorage → 自动登录
   ↓ 自动跳转到原页面，顶部出现「欢迎，xxx」
```

字段校验：

| 字段 | 规则 | 错误提示 |
| --- | --- | --- |
| 邮箱 | 必填，标准 email 正则 | "请输入有效邮箱地址" |
| 昵称 | 可空，留空时取邮箱 @ 前部分 | — |
| 密码 | 必填，**长度 ≥ 6** | "密码至少 6 位" |
| 确认密码 | 必须与密码一致 | "两次输入的密码不一致" |
| 邮箱唯一 | 不能与已注册账号重复 | "该邮箱已注册，请直接登录" |

成功后行为：

- 自动写入 `ielts-reader-accounts` 数组
- 自动设置 `ielts-reader-current-account` 为本次新账号
- 关闭模态框，顶栏右上角从「登录」变为「{邮箱/昵称} ▾」下拉
- 顶栏弹出 2 秒 toast「注册成功，欢迎回来」

##### 4.2.7.3 登录流程（P0）

```
登录表单：
   ┌─────────────────────────────┐
   │  邮箱 [___________________] │
   │  密码 [___________________] │
   │                             │
   │  [登录]   [没有账号？立即注册] │
   │                             │
   │  ⚠️ 提示：本工具为本地演示   │
   └─────────────────────────────┘
```

字段校验：

| 字段 | 规则 | 错误提示 |
| --- | --- | --- |
| 邮箱 | 必填，标准 email 正则 | "请输入有效邮箱地址" |
| 密码 | 必填 | "请输入密码" |

登录校验：

- 邮箱不存在 → "邮箱未注册"
- 密码不匹配 → "密码错误，请重试"
- 校验通过 → 设置 current-account → 关闭模态框 → 顶栏变下拉 → toast「登录成功」

**MVP 简化**：不做「记住我」复选框——只要刷新页面就重新校验（依赖 current-account 持久化）。不做「忘记密码」「邮箱验证」（见 §12 未来扩展）。

##### 4.2.7.7 与现有 localStorage 数据的关系

| 现有 key（v1.0） | 行为变化 |

## 5. 句子成分标注体系（本产品核心）

### 5.1 标注层级

（同 v1.0，未变）

| 层级 | 内容 | 说明 |
| --- | --- | --- |
| L1 主干成分 | 主语、谓语、宾语、表语、宾语补足语 | 句子的「骨架」，必须先划对 |
| L2 修饰成分 | 定语、状语、同位语、插入语 | 句子的「血肉」 |
| L3 从句类型 | 主语/宾语/表语/定语/状语/同位语从句 + 引导词 | 标注从句功能与引导关系 |
| L4 短语结构 | 介词短语、非谓语动词短语（不定式/动名词/分词） | 帮助理解短语内部结构 |

### 5.2 成分类型定义表

（同 v1.0，未变）

| 编码 | 成分名 | 英文 | 功能说明 | 示例（下划线部分） |
| --- | --- | --- | --- | --- |
| S | 主语 | Subject | 句子陈述的对象 | _The rapid growth of cities_ has changed the landscape. |
| V | 谓语 | Predicate Verb | 主语发出的动作/状态 | Cities _have changed_ dramatically. |
| O | 宾语 | Object | 动作的承受者 | The study reveals _a clear trend_. |
| P | 表语 | Predicative | 系动词后的成分，说明主语 | The trend _is_ _obvious_. |
| OC | 宾语补足语 | Object Complement | 补充说明宾语 | The results made _the theory_ _popular_. |
| Attr | 定语 | Attributive | 修饰名词/代词 | The _urban_ landscape changed. |
| Adv | 状语 | Adverbial | 修饰动词/句子，表时间、地点、方式、原因等 | _Over the past century_, cities changed. |
| App | 同位语 | Appositive | 解释说明相邻名词 | Charles Darwin, _the famous naturalist_, … |
| Par | 插入语 | Parenthetical | 独立于句子结构之外的成分 | The result, _however_, was unexpected. |
| Conj | 连接词/引导词 | Connective | 连词、关系代词/副词 | _that_, _which_, _when_, _because_ … |
| Prep | 介词短语 | Prepositional Phrase | 由介词引导的短语，常作定语/状语 | _in the early 20th century_ |
| Inf/Ger/Part | 非谓语短语 | Non-finite Phrase | 不定式/动名词/分词短语 | _to understand the text_, _reading widely_, _driven by demand_ |

**标注规则约定**：

1. 以**主干成分优先**：先划出 S/V/O/P/OC，再处理修饰成分。
2. 一个词可能同时承担多重语法角色时，按**最外层功能**标注（避免重复高亮造成视觉混乱），细节放入 Tooltip 说明。
3. 从句整体作为「一个成分」参与外层句子（如整个宾语从句标为 O），其内部再细分（定语从句内部可再划 S/V 等）——MVP 阶段可仅标注从句整体，内部细分作为 V1.1 增强。
4. 引导词（that/which/when 等）单独标为 Conj，便于识别从句边界。

### 5.3 高亮配色方案（建议）

（同 v1.0，未变）

> 原则：**浅色背景 + 深色文字**，保证长文本可读性；避免使用纯饱和色块遮挡文字。

| 成分 | 建议底色 | 语义 |
| --- | --- | --- |
| 主语 S | `#D6EAF8`（浅蓝） | 稳定、主体 |
| 谓语 V | `#FADBD8`（浅红） | 动作、核心 |
| 宾语 O | `#D5F5E3`（浅绿） | 承受对象 |
| 表语 P | `#FDEBD0`（浅橙） | 说明主语 |
| 宾语补足语 OC | `#D1F2EB`（浅青） | 补充说明 |
| 定语 Attr | `#FCF3CF`（浅黄） | 修饰名词 |
| 状语 Adv | `#E8DAEF`（浅紫） | 修饰/背景信息 |
| 同位语 App | `#FADBD8` 变体（浅粉） | 解释说明 |
| 插入语 Par | `#F2D7D5`（浅棕粉） | 独立成分 |
| 连接词 Conj | `#E5E7E9`（浅灰，加下划线） | 结构连接 |
| 介词短语 Prep | 无底色 + 虚线边框 | 短语结构 |

## 6. 交互与界面设计

### 6.1 页面布局（移动端优先）

**v1.0.1 顶栏更新**：

```
┌───────────────────────────────────────────┐
│ 雅思句子成分精读       12/58   [登录/账号]│ ← 右上角新增账号入口
├───────────────────────────────────────────┤
│                                           │
│   正文区（段落+句子）                      │
│   · 已读句子（保留标注，可回看）            │
│   · 【当前句】（成分高亮+标签）             │
│   · 未读句子（低对比度）                   │
│                                           │
├───────────────────────────────────────────┤
│ 底部控制条：                              │
│  [上一句] [下一句] [译] [☆]              │
├───────────────────────────────────────────┤
│ 图例（可折叠）· 标注开关 · 难句            │
└───────────────────────────────────────────┘
```

- **桌面端**：正文区居中（最大宽度约 720px），图例固定在右侧栏。
- **移动端**：正文全宽，图例以抽屉/折叠面板形式从底部呼出。
- **顶栏账号入口布局**：
  - 未登录：右上角一个按钮「登录」
  - 已登录：右上角「邮箱/昵称 ▾」下拉菜单，包含同步占位 + 退出登录
  - 移动端：账号入口挤占空间时，简化为纯文字「登录」/「退出」按钮

**状态设计**：

- `未读`：低对比度灰字，无高亮。
- `当前`：正常对比度 + 成分高亮 + 标签 + 进度高亮。
- `已读`：**仅保留句子文本，移除成分标注**；整体弱化（透明度略降）；可点击回看临时显示该句标注。
- `未登录/已登录`：顶栏右上角切换（见 §4.2.7.4）。

### 6.2 核心交互流程

**未登录态**：

```
打开文章
  → 第一句自动进入「当前」状态，成分高亮展示
  → 用户阅读 + 点按成分查看说明（可选）
  → 点击「下一句」/空格/→
  → 下一句进入「当前」状态，成分高亮刷新
  → …循环…
  → 最后一句读完 → 完成小结
```

**v1.0.1 登录态**：

```
打开页面
  → 检查 localStorage 是否有 current-account
     → 有：自动进入已登录态（顶栏显示账号下拉）
     → 没有：保持未登录态（顶栏显示「登录」按钮）
  → 阅读主流程同未登录态
  → 顶栏可随时点开下拉退出登录
```

### 6.3 关键交互细节

| 交互 | 行为 |
| --- | --- |
| 进入下一句 | 按钮 / `空格` / `→` / 点击目标句子；自动平滑滚动到当前句并高亮 |
| 查看成分说明 | 点按（移动端）/ 悬停（桌面端）高亮区块 → 弹出 Tooltip |

| 收藏难句 | 句尾「☆」一键收藏，实心表示已收藏 |
| 句子跳转 | 打开句子列表（按段落分组）点选任意一句 |
| **v1.0.1 hotfix**：标注范围切换 | 单句 / 全文二选一；默认「单句」（仅当前句显示成分标注）；切到「全文」时所有句子显示标注 |
| 换一篇文章 | 文章选择页，按「剑桥雅思第几册/Test/Passage」组织 |

### 6.4 边界与异常

- **断点续读**：记录用户读到第几句，下次打开直接恢复到上次位置（`localStorage`）。
- **无网络**：标注数据随页面本地加载，离线可用；账号体系离线完全可用（数据全本地）。
- **屏幕过窄/文字过长**：句子自动换行，高亮区块跨行时保持连续底色，不折断。
- **v1.0.1 新增**：换浏览器/清缓存/隐私模式 → 账号丢失，提示「本机账号丢失，请重新注册」（不强求云备份）
- **v1.0.1 新增**：同一浏览器两个账号交替登录 → 进度/收藏会被新账号操作覆盖（见 §4.2.7.7 MVP 简化说明）
- **v1.0.1 新增**：邮箱格式错误 / 重复注册 / 密码不一致 → 表单内联错误提示，不弹模态层

## 7. 内容与数据需求

### 7.1 文章内容来源

（同 v1.0，未变）

- 首期（MVP）：**预置标注好的剑桥雅思真题文章**（建议从较新的 C9–C18 中挑选，覆盖不同题材：科技、社会、自然、历史等）。
- ⚠️ **版权风险**：剑桥雅思真题受版权保护。建议处理方式（三选一，需与版权方确认）：
  1. 仅用于**个人学习工具**，不公开分发文章全文，用户自行提供文章；
  2. 获取官方授权；
  3. 采用「用户导入文章 + AI 自动标注」为主路径，规避原文存储分发问题（推荐作为长期方向）。
- 当前实现采用**自撰示范文章**路径（1 篇《城市农业与食品安全》，10 句），不分发任何真题原文。

### 7.2 标注数据格式（JSON Schema 建议）

（同 v1.0，未变）

```json
{
  "article": {
    "id": "c18-t1-p1",
    "title": "Urban Landscapes",
    "source": "Cambridge IELTS 18, Test 1, Passage 1",
    "paragraphs": [
      {
        "id": "p1",
        "sentences": [
          {
            "id": "s1",
            "text": "The urban landscape has changed dramatically over the past century.",
            "translation": "在过去的一个世纪里，城市面貌发生了巨大变化。",
            "grammarHint": "本句为简单句：主语 The urban landscape，谓语 has changed，状语 over the past century。",
            "components": [
              { "start": 0,  "end": 19, "type": "S",   "label": "主语",     "note": "名词短语作主语" },
              { "start": 20, "end": 31, "type": "V",   "label": "谓语",     "note": "现在完成时" },
              { "start": 32, "end": 44, "type": "Adv", "label": "状语",     "note": "介词短语作时间状语" }
            ]
          }
        ]
      }
    ]
  }
}
```

- `start` / `end` 为成分在 `text` 中的**字符区间**（含头不含尾）。
- 支持可选字段 `parent` 表示嵌套关系（V1.1 启用）。
- 数据可内嵌进 HTML（符合本项目「单文件、无依赖」风格），或作为独立 JSON 资源加载。

**v1.0.1 补充**：账号数据 schema 见 §4.2.7.1。

### 7.3 标注生产方式

（同 v1.0，未变）

| 方式 | 说明 | 适用 |
| --- | --- | --- |
| 人工标注 | 语法专家逐句标注，质量最高、成本高 | 首期预置文章 |
| AI（LLM）自动标注 + 人工抽检 | 大模型按上述 Schema 输出成分标注，人工复核 | 规模化、用户导入功能 |
| 纯规则解析器 | 依赖 NLP 语法树，长难句准确率有限 | 不推荐作为唯一方案 |

> 建议：MVP 用**人工标注**保证首批文章质量；V1.5 引入**AI 自动标注 + 人工抽检**支撑用户导入。

## 8. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 首屏加载 ≤ 2s；单句高亮渲染 ≤ 50ms；长文章（60+ 句）滚动流畅 |
| 兼容性 | 主流移动/桌面浏览器（iOS Safari、Android Chrome、Chrome、Edge） |
| 响应式 | 移动端优先，桌面端自适应（与仓库现有游戏布局风格一致） |
| 离线 | 预置文章及标注数据本地可用，无网络依赖；**v1.0.1 起账号体系完全离线可用** |
| 可访问性 | 提供色盲友好配色模式；文字对比度达标；支持键盘操作 |
| 数据安全（阅读数据） | 阅读进度、收藏记录存于 `localStorage`，不采集个人数据 |
| 可扩展性 | 标注数据格式向后兼容，新增成分类型不破坏旧数据 |

### 8.1 v1.0.1 新增：账号与隐私

#### 8.1.1 密码存储（重要免责）

**v1.0.1 密码以明文形式存储于浏览器 `localStorage`**。

- **仅适用于个人设备本地演示**：本工具是个人学习工具，非生产系统。
- **风险**：任何能访问该浏览器 `localStorage` 的人（含恶意脚本、XSS、同设备他人）都能读取明文密码。
- **缓解措施**：
  - 不在登录/注册表单上做密码强度展示，避免给用户"很安全"的错觉
  - 在登录/注册模态框底部加一行提示："⚠️ 本工具为本地演示，账号仅保存在本机浏览器中"
  - PRD 文档、UI 上均显式声明 v1.0.1 是 demo 级账号体系
- **未来路线**：v1.5 接云同步时同步升级为「前端哈希 + 后端 bcrypt」方案

#### 8.1.2 账号可见范围

- 账号列表（`ielts-reader-accounts`）仅在当前浏览器可读
- 不同浏览器、不同设备、不同隐私窗口之间**不共享账号**
- 不向任何远端发起账号相关请求（v1.0.1 是纯前端 mock）

#### 8.1.3 隐私边界

- 不采集：真实姓名、手机号、地理位置、设备指纹
- 采集：仅邮箱 + 密码（明文）+ 注册时间 + 昵称（可选）
- 不用于：第三方广告、用户画像、跨产品追踪
- 用户删除账号路径：v1.0.1 **暂未提供**（MVP 简化），可手动 `localStorage.removeItem('ielts-reader-accounts')`

## 10. 验收标准（MVP）

- [ ] 打开一篇文章，默认仅第一句处于「当前」高亮状态，其余句子低对比度。
- [ ] 当前句的主语/谓语/宾语/定语/状语等成分用不同颜色正确高亮，且区间与原文单词精确对应。
- [ ] 点击「下一句」/空格/→，高亮正确切换到下一句，上一句转为「已读」且标注可回看。
- [ ] 图例颜色与实际高亮一致，且可点击某类成分进行聚焦/隐藏。
- [ ] 读至最后一句后出现完成小结；刷新页面能恢复到上次进度。
- [ ] 手机端布局不溢出，长句换行后高亮区块连续不断裂。
- [ ] 中文翻译可折叠展开，收藏功能可用。
- **v1.0.1 hotfix**：
- [ ] 默认进入「单句模式」：只有当前句显示成分标注；非当前句（含未读和已读）只显示句子原文
- [ ] 「标注范围切换」按钮可切换到「全文模式」，所有句子显示成分标注
- [ ] 切换状态在刷新页面后保持（持久化到 localStorage）
- **v1.0.1 新增**：
- [ ] 顶栏右上角未登录态显示「登录」按钮，已登录态显示账号下拉菜单。
- [ ] 点击「登录」弹出登录模态框；底部有「立即注册」链接切换到注册表单。
- [ ] 注册表单：邮箱、密码（≥6 位）、确认密码、昵称（可选），校验内联提示。
- [ ] 注册成功后自动登录，顶栏切换到下拉菜单，弹出注册成功 toast。
- [ ] 登录成功后刷新页面，自动保持登录态（不需重新登录）。
- [ ] 退出登录需二次确认；确认后顶栏恢复「登录」按钮，账号从 current-account 移除。
- [ ] 点击「同步」按钮弹出「开发中」toast，不发起任何网络请求。
- [ ] 注册/登录模态框底部有「本机存储」免责提示文案。

## 11. 风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 文章版权 | 法律风险 | 以「用户导入」为主路径，或取得授权，避免分发全文 |
| 标注质量 | 用户信任 | 首期人工标注 + 审校；AI 标注加人工抽检 |
| 成分划分存在语法争议 | 用户困惑 | 提供 Tooltip 说明 + 允许标注规则注明出处（如「按 XX 语法体系」） |
| 长难句嵌套复杂 | 视觉混乱 | 分层标注 + 焦点高亮，避免全屏彩色 |
| 单文件体积（多篇文章内嵌） | 加载变慢 | 文章按需加载，正文与标注数据分离 |
| **v1.0.1 新增：账号系统复杂度** | 开发量被低估 / 测试覆盖不全 | §4.2.7 严格收窄 MVP 范围（不做验证/找回/多端同步）；UI 自动化冒烟测试 |
| **v1.0.1 新增：明文密码存储风险** | 用户误以为很安全，在公用电脑上注册 | §8.1.1 UI 与 PRD 双重免责声明；引导用户仅在个人设备使用 |
| **v1.0.1 新增：换设备/清缓存导致账号丢失** | 用户挫败感 | UI 提示「本机存储，换设备需重新注册」；v1.5 接云同步时彻底解决 |

## 12. 待确认事项（Open Questions）

> v1.0.1 已落地「账号体系」主线，本节聚焦**未来扩展**类问题。

1. **真实云同步方案（v1.5）**：是用 Firebase / Supabase BaaS，还是自建 Node 后端？两种方案的合规与运维成本差异需要评审。
2. **密码升级路径（v1.5）**：从明文升级到「前端哈希 + 后端 bcrypt」时，老账号如何平滑迁移？强制重置密码还是首次登录时升级？
3. **第三方登录（v2.0？）**：是否引入微信 / Google / GitHub 登录？涉及第三方 OAuth 接入合规问题。
4. **多账号数据隔离（v1.5）**：账号与阅读数据的绑定粒度——是账号级共享，还是每个账号完全独立？两种方案对用户心智模型的差异需要 UX 评审。
5. **账号删除路径（v1.0.1 暂未提供）**：是否在 v1.0.2 提供"删除我的账号"按钮？涉及 GDPR / PIPL 合规边界。

## 附录 A：典型长难句拆解示例

（同 v1.0，未变）

> 原文：**The rapid expansion of cities, which began in the nineteenth century, has fundamentally altered the way that people live and work.**

| 成分区间 | 类型 | 说明 |
| --- | --- | --- |
| The rapid expansion of cities | 主语 S | 名词短语，核心词 expansion |
| which began in the nineteenth century | 定语从句 Attr | 修饰主语中的 cities/expansion，非限制性定语从句 |
| has fundamentally altered | 谓语 V | 现在完成时 |
| the way that people live and work | 宾语 O | 名词短语，内含 that 引导的定语从句修饰 the way |

    │             │
    │             └─→ 点「登录」→ 弹登录模态框
    │                              │
